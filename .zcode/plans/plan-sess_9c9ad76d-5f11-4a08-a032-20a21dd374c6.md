- tokens 表过期 GC：auth 服务启动时 + 定期清理过期 token（当前无限增长）

**S2 数据完整性**

## 第二部分：Router/Cache v0.6 产品化（3 个提交，约 2 天）

探索关键发现：`inferMode` 是死代码（系统提示里根本没有 `Mode:` 标记）；流式调用完全绕过 Router 成本记录；Cache 没有任何集成层；`ProviderRegistry.Add` 更新时丢价格字段；生产 gateway 从不填价格（成本恒 0）。

**R1 显式 mode 贯通 + Router 接线**
- 新增 `modelgateway.WithMode(ctx, mode)` context 键（沿用 toolregistry.WithRunID 的 ctx 模式，零接口改动）；orchestrator `streamModelCall`/`fallbackModelCall` 调用前注入 `run.Mode`
- Router 的 `Chat`/`StreamChat` 从 ctx 读 mode；**删除 `inferMode`**（doc/22 既定决策）
- 修 `ProviderRegistry.Add` 丢 `PricePer1KInput/Output` bug；`initModelGateway` 增加 `GEOWORK_LLM_PRICE_INPUT/OUTPUT` 环境变量填价格
- `main.go`：单 provider 时 Router 包装（AddProvider + 默认规则），再套 RateLimitedGateway，保持 nil-interface 纪律
- 测试：mode 路由命中规则、无规则走默认、fallback 生效

**R2 流式成本 + 预算 + 重试**
- Router `StreamChatWithFallback` 包一层 channel 观察尾部 Usage chunk 记成本（当前流式零记录）
- `CostController` 接线：`GEOWORK_LLM_DAILY_BUDGET/MONTHLY_BUDGET` 环境变量，0=不启用；预算超限返回明确错误（run 失败可见原因）
- 实现悬空的 `RoutingRule.MaxRetries`（ChatWithFallback 内按 ctx 重试）
- 测试：流式 usage 进 CostController、预算拦截、重试次数

**R3 CachedGateway 装饰器**
- 新建 `CachedGateway`（复制 RateLimitedGateway 装饰器形态）：**仅缓存非流式 Chat 且响应无 tool_calls**（纯文本响应才安全，摘要类调用是主要受益者）
- 修 cache 缺陷：key 改 hex 编码（当前含任意字节）、Get 时清除过期项、Get 刷新时间戳（LRU 语义）
- `GEOWORK_LLM_CACHE=1` 环境变量启用（默认关）；接线顺序 Cache→Router→RateLimit
- 测试：命中/未命中、TTL 过期、带 tools 请求不缓存、tool_calls 响应不缓存

验收：`go test ./...` 全绿；Router/Cache 头部 EXPERIMENTAL 注释移除，doc/22 §6 对应条目更新。

## 第三部分：Windows 沙箱隔离 D-B3-B（3 个提交，约 2.5 天）

探索关键发现：两条执行路径互相独立（`sandbox.Service` HTTP API 与 `toolregistry` builtin tools，后者才是模型真正驱动的路径且完全没有 SysProcAttr）；`service_windows.go` 的 `setSysProcAttr` 是空结构体，天然插入点；超时只杀直接子进程，孙进程逃逸。

**W1 Job Object 地基**（新增依赖 `golang.org/x/sys/windows`）
- 新包 `core/internal/sandbox/jobobject`（build tag 分平台）：创建 Job Object（`JOB_OBJECT_LIMIT_PROCESS_MEMORY` + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`），`cmd.Start()` 后 assign——关句柄即杀全进程树，超时真正可靠
- 统一 spawn helper：`sandbox.Service` 与 builtin tools（run_shell/run_python）共用，堵住"只隔离一条路径"的洞；git 类工具不进 job（低风险且需要正常权限）
- Unix 对等：已有 `Setpgid` 基础上补进程组杀（timeout 杀 -PGID）
- 测试：孙进程随超时被杀（Windows/Unix 各一条）、内存超限进程被终止、job 未启用时行为不变

**W2 低完整性令牌**
- 子进程用低完整性 level token 启动（`SysProcAttr.Token`），限制写盘范围到 Low IL 路径之外
- 创建失败（权限不足/策略限制）→ 诚实降级：记 warn 日志 + 审计事件标注"隔离未生效"，不阻塞执行（D-B3 诚实化原则延续）
- 测试：令牌创建成功路径、失败降级路径（mock 或跳过标记）

**W3 策略贯通 + 诚实清单更新**
- `SandboxPolicy.MaxMemoryMB` 从死字段变为 job object 内存上限的真实来源（配置链路：policy → spawn helper）；`NetworkAccess` 字段删除（Job Object 不管网络，诚实化）
- Python runner docstring 与 Go 侧文档更新"强制/未强制"清单：内存上限✅、进程树终止✅、低完整性写盘限制✅（best-effort）、网络隔离❌未强制
- 验收：`go test ./...` 全绿 + 手工验证 run_shell 跑 `start /b` 派生孙进程场景被完整终止

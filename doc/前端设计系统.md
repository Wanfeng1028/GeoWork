## 一、设计原则

1. **骨架克制**：圆角只三档、间距只用 4 的整数倍、阴影极淡。秩序感来自参数一致，不是装饰。
2. **色彩即状态**：颜色的第一职责是让用户一眼分辨 Agent 的 idle / planning / running / waiting / success / failed。
3. **明暗同权**：暗色是 GIS 画布的自然底盘，亮色是会议室投屏刚需。两套同做、同标准、同验收。
4. **品牌原生**：所有色彩从深海军蓝 `#071225` 派生，不从 antd 默认蓝出发。

## 二、主题策略

### 2.1 入口收敛

| 主题 | 状态 |
|---|---|
| 跟随系统 | ✅ 保留（指向 editorial / editorial-dark） |
| **editorial-light（亮色旗舰）** | ✅ 打磨 |
| **editorial-dark（暗色旗舰）** | ✅ 打磨 |
| 晴空 light / 暗色 dark / 插画 / 玻璃 | ⛔ 关闭入口（代码保留，随时可复活） |

「关闭」只动用户可见的菜单（AppMenu 的 themeChildren + 设置页中的主题选项），主题文件和 `themes/index.ts` 一行不动，保证 React Hooks 顺序稳定。

### 2.2 切换契约

- 明暗切换时**层级不变、只变明暗**：同一组件在两套里的视觉深度完全一致。
- 所有 Token 必须同时给出明/暗两版本，禁止只写一套。

## 四、形状 / 圆角 / 间距

### 4.1 圆角（三档，禁止散装）

| 档位 | 值 | 用于 |
|---|---|---|
| SM | `4px` | Tag、Badge、代码块、Tooltip、小图标容器 |
| MD | `8px` | 按钮、输入框、Select、菜单项、卡片内元素 |
| LG | `12px` | 卡片、弹窗、下拉面板、对话气泡 |

> **唯一例外**：胶囊族组件（CapsuleButton / CapsuleTabs / CapsuleTag / CapsuleGhost）使用 `9999px`，见 §10.1。其余组件引用 `9999px` 视为违规。

### 4.2 间距（4 的整数倍）

```
4 · 8 · 12 · 16 · 20 · 24 · 32 · 48
```

- 组件内 padding ≤ 16
- 卡片之间 gap = 12 或 16
- 页面边距 = 24 或 32
- 对话流	max-width 720px 居中

### 4.3 字号与行高

| 级 | 字号 | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| H1 | 20 | 1.4 | 600 | 页面标题 |
| H2 | 16 | 1.5 | 600 | 区块标题 |
| Body | 14 | 1.6 | 400 | 正文 |
| Dialogue | 14 | 1.7 | 400 | Agent 回复（阅读优先） |
| Caption | 13 | 1.5 | 400 | 辅助信息 |
| Small | 12 | 1.4 | 400 | 时间戳 / Tag |

规则：
- 数字、commit hash、坐标、CRS、路径、命令行一律 **`JetBrains Mono`**；
- 侧栏任务标题 = `13px / 500`；时间戳 = `12px / 三级色`。

## 七、布局骨架

> 原则：**主区只有一种"内骨"**——对话流和工作台共用同一套布局，只是内容不同。
> 原则：**收起无痕**——面板收起时既不显示把手，也不留下可见的边框或背景块。
> 原则：**开合在顶栏**——所有面板的展开/收起按钮都放在顶栏，不藏在悬停区或角落里。

### 7.1 三段式 Agent 工作区

GeoWork 全站只有一种整体骨架：

```
┌────────┬───────────────────────┬─────────────────┐
│ rail   │   主区                 │   右侧面板        │
│ 一级导航│  (对话/画布/表单)        │  (工具/上下文)    │
│  56px  │   灵活宽度               │   320px 可调      │
│        │                       │   可整体隐藏       │
└────────┴───────────────────────┴─────────────────┘
     ↑               ↑                    ↑
 一级入口          正在干啥的工作区        工具/面板
 (新任务/         输入底吸 (对话页)      (审查/终端/
  定时任务/                              辅助对话/…)
  扩展/…)
```

| 区块 | 宽度 | 职责 | 说明 |
|---|---|---|---|
| rail | 固定 56px | 一级功能入口 | 图标 + tooltip，永不展开文字 |
| 主区 | flex 1 | 当前工作内容 | 对话流 / 地图工作台 / 表单 / 列表 |
| 右侧面板 | 320px，可拖拽 240–480 | 工具/上下文 | **常驻第三列**，收起后主区占满无残留 |

**铁律（不可违反）：**
1. **面板开合控制点只在顶栏**——展开/收起按钮永远在顶栏右侧一组功能图标里，不允许藏在悬停区；"收起"后该位置没有任何把手、边框或背景残留。
2. **主区内骨唯一**——对话流页和地图工作台只是"内容换料"，骨架（输入框吸底、单列居中、间距节奏）完全一样。
3. **右侧永不出现"隐藏的提示条"**——收起后屏幕右边就是干净的 Level 0 背景，没有灰色细条、没有把手。

### 7.2 12 列隐形网格系统

所有水平宽度对齐到同一套"刻度"，不可见但强制：

```
|col|col|col|col|col|col|col|col|col|col|col|col|
 ←- gutter 16px (内容≥1920) / 12px (1280-1919) / 8px (<1280) -→
```

水平刻度（宽度→对应的可见区块）：

| 刻度 | 用于 |
|---|---|
| 56px | rail（一级导航） |
| 260px | 侧栏二级导航（展开） |
| 320px | 右侧面板（默认） |
| 720px | 对话流内容宽度（居中） |
| 48px | 卡片 padding-l/r |
| 24px | 页面 padding |

**规则**：任何元素宽度必须是"刻度值"或"刻度值的整倍数"。不允许出现 712px、350px 这种"自己编的尺寸"。

## 八、反馈状态三件套

> 任何页面在任何时刻都必须落在"有数据 / 加载中 / 空状态 / 报错"四种之一，不允许"留白"。

### 8.1 骨架屏（加载中）

按页面模板选用：

| 模板 | 骨架形态 |
|---|---|
| A 对话流 | 4 条消息骨架（宽 60%/80%/70%/90% 错落的灰条） + 底部输入框占位 |
| B 工作台 | 左树 = 8 行树节点骨架条；地图区 = 浅灰网格占位底 |
| C 列表 | 页头标题骨架 + 6 行表格骨架（行高 48） |
| D 表单 | 标题骨架 + 5 组字段骨架（label 条 + input 条） |

通用样式：
- 骨架条背景 = `colorFillSecondary`，顶部一层微光（dark `rgba(255,255,255,0.04)` / light `rgba(15,23,42,0.05)`）从左到右 1.5s 循环；
- 圆角 = 它要占位的那个元素的圆角；
- 禁用：满屏居中大菊花（antd Spin）——骨架优先于 spinner。

### 8.2 空状态（无数据）

按第十节"空状态设计"执行。骨架→空态切换时**布局不跳变**：两者的标题位置、引导按钮位置在同一像素。

### 8.3 报错（操作失败/网络异常）

**位置分级**：

| 级别 | 形态 | 用法 |
|---|---|---|
| 字段级 | 文字红 + 字段底淡红 | 表单校验失败 |
| 块级 | 卡片状态条（左侧 3px 红条） | 某个模块失败 |
| 页面级 | 页头下方一条横幅（48px 高，淡红底） | 整个页面加载失败 |
| 全局级 | 右上角滑出 toast（8s 自动消失，可关闭） | 网络断开等跨页 |

**文案规则**：错误提示只说"是什么 + 怎么办"两件事，不贴原始异常堆栈。原始堆栈放 toast 的"复制详情"里。

**重试**：页面级 / 块级报错必须带「重试」ghost 按钮；字段级不带按钮，靠重新输入消除。

### 10.1 胶囊按钮（CapsuleButton）与胶囊切换器（CapsuleTabs）

#### 10.1.1 设计意图

来自产品主人的个人博客项目 BlogAstroPure：
- **胶囊切换器**：药丸形容器内多个选项平铺，选中项以高亮色块呈现并可带数量徽标（"全部 4 / Projects 2 / Certificates 2 / Publications 0"）；
- **胶囊按钮**：全圆角实色按钮（"‹ Back"），识别度高。

为什么引入：现有 Segmented 切换器（9.1）是方角矩形 IDE 风格；胶囊形态更亲和，适合任务分类筛选、状态过滤等"轻量切换"场景。

**关键决策**：BlogAstroPure 的选中色为 Gemini 蓝渐变 `#3186ff → #4ea0ff`，**不是** GeoWork 品牌色。为避免新色彩分裂——**形态照搬（9999px 全圆角）、颜色改穿品牌色**。源参数见原仓库 `src/assets/styles/global.css` 中 `.gemini-btn` 与 `.gcard-tag` 两处。

#### 10.1.2 适用范围（v1.4.1 扩张后）

| 组件 | 用于 | 与 Segmented 的关系 |

| CapsuleGhost（胶囊虚钮） | ghost 次级按钮 | 透明底 + 细边框 |

## 十七、工程纪律

> 前面十五章是"应该长什么样"，本章是"怎么保证不走样"。本章每条都必须能被工具或流程强制执行。

### 17.1 目录边界

| 目录 | 允许放什么 | 禁止 |
|---|---|---|
| `src/app/themes/` | 主题 token 文件 | 禁止出现具体页面样式 |
| `src/shell/` | AppShell 骨架组件 | 禁止出现业务逻辑 |
| `src/pages/<Page>/` | 该页私有组件（不被其他页引用） | 禁止页面间互相 import 内部组件 |
| `src/shared/` | 无 UI 的 hooks / stores / utils | 禁止放组件 |

共享组件判定：被 2 个及以上页面使用 → 必须上移到公共位置并在文档登记；只允许一个页面用的组件禁止上移。

### 17.2 样式硬约束（stylelint 落地）

以下规则写进 `stylelint.config`，违规即 CI 红：

| 规则 | 内容 |
|---|---|
| `color-no-hex` | CSS 中禁写 `#xxx` 色值（例外：`themes/*.ts`、文档） |
| 间距检查 | padding/margin/gap 的值必须是 4 的整数倍 |
| 圆角检查 | border-radius 只允许 4 / 8 / 12 |
| 字号检查 | font-size 只允许 12 / 13 / 14 / 16 / 20 |
| `!important` | 默认禁止；如需覆盖 antd 深层样式，须在该行加注释说明原因 |

### 17.3 新组件准入

新增任何组件前，按顺序自问：

1. antd 原生能不能满足？→ 能就用原生，靠 token 覆写达到视觉效果
2. 设计系统第十五节之前的规范里有没有对应规格？→ 没有就**先在文档补规格，再写组件**
3. 组件 props 是否只接收数据，不接收样式字符串？→ 禁 `<Card color="#xxx">` 这种 API

### 17.4 PR 门槛

| 检查项 | 方式 |
|---|---|
| stylelint / oxlint 全绿 | CI 自动 |
| 第二十一节验收清单逐条过 | PR 描述中逐项勾选 |
| 涉及主题的改动 | 必须附暗色 + 亮色两张截图 |
| 新组件 | PR 描述里说明"满足 17.3 的第几条" |
### 17.5 主题切换过程（纪律子条目）

| 项 | 规定 |
|---|---|
| 存储 key | `geowork:appearance`，值域 `system / editorial / editorial-dark` |
| 读取时机 | 应用启动时同步读取（localStorage），禁止闪白后再切换 |
| system 解析 | `window.matchMedia('(prefers-color-scheme: dark)')`，监听其 `change` 事件实时跟随 |
| 切换过渡 | `background-color / color / border-color` 加 `transition: 150ms ease-out`，仅在切换瞬间生效（`.theme-switching` 类挂 200ms 后摘除），避免全站常驻 transition 影响性能 |
| 禁止 | 切换动画超过 250ms；禁止加"太阳/月亮旋转"等花哨过渡 |

## 十八、验收基线

> 验收清单（PR checklist）是"过程防线"，本节是"目标防线"：**所有页面最终长什么样，拿样板间对照。**

### 18.1 样板间

| 项 | 规定 |
|---|---|
| 视觉基线页面 | **任务对话页**（Tasks → 任一任务详情） |
| 覆盖要素 | 对话流、工具调用卡、状态 Tag、输入框工具条、Segmented、滚动条 |
| 对照方式 | 本文档 + 基线截图双重对照；任何页面与样板间气质明显不符即打回 |
| 基线更新 | 设计系统版本升级时同步重截基线 |

### 18.2 基线快照要求

每个版本维护两组基线（存 `doc/baseline/`）：

| 文件 | 内容 |
|---|---|
| `baseline-dark.png` | 暗色主题下样板间整窗截图 |
| `baseline-light.png` | 亮色主题下样板间整窗截图 |

截图要求：窗口 1600×1000、无缩放、含侧栏与右面板展开态。

### 18.3 落地顺序（照着做，不跳步）

1. 本节生效后，第一优先级是把"任务对话页"改到符合全文规范；
2. 对话页过验收清单全部条目后，截图存档两份基线；
3. 此后每改一个页面，与该基线左右对照，差距明显即返工；
4. 其他页面（首页/工作台/列表/设置）按模板 A/B/C/D 逐页向基线靠拢。

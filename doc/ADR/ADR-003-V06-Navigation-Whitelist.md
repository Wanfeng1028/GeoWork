# ADR-003: v0.6 导航白名单（只减不增，恢复需走 ADR 修订）

## 状态：已接受（2026-08-19）

## 背景

2026-08-19 全量核查（doc/27 §2 九域现状表）确认：13 条路由中约一半是占位页、死代码或 mock 数据页。产品面长期处于"看到竞品有什么就补什么界面"的界面驱动状态，导致：

- 用户对桌面软件的信任被完成度最低的界面摧毁（假快捷键、永远空的占位页）
- 没有"完成"的定义，界面数量无限增长而完成度不涨
- 41 处"后续接入/敬请期待"文案构成系统性假承诺

对标产品（Codex/Cursor 式 agent 工作台）的骨架是 chat-first 单一工作区，不是页面集市。

## 决策

**v0.6 导航冻结：白名单只减不增，任何新页面/恢复被砍页面必须走 ADR 修订。**

| 处置 | 页面 | 理由 |
|---|---|---|
| ✅ 保留 | 新任务（NewTask） | 核心工作流，真实完成度高（SSE/审批卡/三态齐全） |
| ✅ 保留 | 定时任务（Tasks） | 三态最完整，接 `/api/db/tasks` 真实数据 |
| ✅ 保留 | 设置（Settings/About） | 功能密度高；数据源 localStorage→API 列入后续（doc/27 域 8） |
| ⏳ 分诊后定去留 | Extensions 四页（Skills/MCP/Connectors/Experts） | 后端端点存在但前端全 mock；第 2 周 W2-3 产出"接/留/砍"清单，四页可能收敛成一页 |
| ❌ 移出导航 | MobileControl | 绑定/启用全是占位 toast，无后端 |
| ❌ 移出导航 | Workspace | 600ms 假 loading 后永远空态，无真实功能 |
| ❌ 移出导航 | DataCenter | 21 行路由占位页 |
| ❌ 移出导航 | AgentStudio | 21 行路由占位页 |
| 🗑 删除文件 | DashboardPage | 死代码，从未挂路由 |
| 🗑 删除文件 | ThemePreviewPage | 已下线但文件保留，且 GlobalSearchModal 仍收录死条目 |
| 🗑 删除文件 | components/ErrorBoundary | 死代码，与 shell/feedback/ErrorBoundary 重复 |
| 🗑 删除文件 | 4 个 @deprecated 主题（bootstrap/illustration/glass 等） | app/themes/index.ts 已标注下线待复活 |

**GIS 地图工作区是 v1.0 的事，v0.6 不装。**

## 配套纪律

1. **DoD 三条**（AGENT.md §4）：真 API、三态齐全、错误兜底，三者不齐的界面不得进导航
2. 被移出导航的页面在第 4 周清场时删除路由与入口；文件删除随 W4-1 工单
3. 白名单外的"后续接入"文案入口一并清除（41 处中白名单外部分）

## 后果

**正面**：

- 产品面只剩真功能，"不协调感"的根源（假界面）被系统性移除
- 范围有了边界，施工可以收敛——"什么时候写完"第一次有了答案
- 与 doc/21 D1 决策精神一致："宁可诚实地空着，不假装在工作"

**负面/代价**：

- 导航变短，短期内"看起来功能变少了"——这是诚实的代价，换信任
- 分诊结论（扩展四页去留）是产品决策，可能推翻本表部分行——以 W2-3 清单为准修订本 ADR

**回滚**：恢复任何被砍页面需提交 ADR 修订说明理由，不许顺手加回。
